# PeachOS TV · мастер для Windows

Обычный APK остаётся самостоятельным лаунчером. Этот **необязательный** мастер устанавливает APK через ADB и помогает выбрать, какие пакеты отключить. Python и права администратора для собранной Windows-версии не нужны.

По умолчанию открывается **простой установщик**: подключите устройство, проверьте план, установите. Если PeachOS уже установлен, автоматически предлагается обновление до версии, встроенной в EXE, с сохранением данных и порядка приложений. Лёгкая очистка необязательна и выключена; она использует только рекомендованные правила и сохраняет все перечисленные функции. На новой установке можно назначить Home; для проверенного Xiaomi обход штатного Home явно указан в плане.

Кнопка **«Расширенный мастер»** открывает четыре раздела с боковой навигацией: «Устройство», «Приложения», «Очистка», «Копии». Внутри — очередь APK, ручной выбор пакетов и восстановление. Страницы прокручиваются; основные действия и короткий итог плана остаются отдельно от подробностей. Это не опасный режим: экспертное отключение защиты включается отдельно, с предупреждением. При возвращении в простой установщик экспертная защита включается обратно.

Переключатель **«Тёмная тема»** в шапке меняет оформление сразу, сохраняя введённые данные и выбор. Настройка запоминается в `PeachOS-TV-data/ui-settings.json` рядом с EXE. По умолчанию используется светлая тема; системные окна выбора файлов и уведомления используют оформление Windows.

В разделе «Приложения» есть кнопка **«Только обновить»**. Этот план устанавливает только встроенный APK через `adb install -r`, не меняет Home и не отключает пакеты, даже если в расширенном мастере что-то было выбрано. Он требует уже установленный пакет PeachOS. Это обновление до версии из скачанного мастера, а не поиск последнего релиза в интернете. Ошибки подписи, несовместимости и запрет понижения версии сообщает Android; удалять старую установку мастер не будет.

## Необязательный модуль AirPlay — прототип

Если сборка мастера содержит отдельный APK приёмника, в простом и расширенном режимах появляется **выключенный по умолчанию** пункт «Дополнительно: AirPlay с iPhone». Без выбора этого пункта модуль не устанавливается, а в контрол панели лаунчера остаётся лупа. Установка модуля заменяет только эту кнопку переключателем AirPlay: включённое состояние отмечается синим значком. Компоновка панели сохраняется. Снятая галочка не удаляет уже установленный модуль и не меняет его настройки.

При включённом приёмнике iPhone в той же сети выбирает **Пункт управления → Повтор экрана → PeachOS TV**. Полноэкранное окно приёмника должно открываться при подключении; после остановки трансляции на телефоне возвращается предыдущий экран. Для автоматического открытия поверх другого приложения модуль отдельно запросит системное разрешение «Поверх других приложений». **Мастер не выдаёт это разрешение и не включает трансляцию автоматически.** Работа с реальным iPhone пока проверяется; защищённое DRM-видео не заявлено поддерживаемым.

Мастер проверяет версию Android и пересечение архитектур **операционной системы** с нативными библиотеками выбранного APK до первой установки или очистки. Текущий прототип требует Android 7.0+; APK с единственной `armeabi-v7a` не предлагается Android, поддерживающему только `arm64-v8a`. 64-битный процессор сам по себе не определяет поддержку 32-битных приложений. Неизвестная архитектура не считается совместимой. Несовместимость отключает галочку с объяснением, но не мешает установить обычный лаунчер.

Выбранный модуль виден отдельной строкой плана; его SHA-256, роль и результат установки записываются в `restore.json`. При ошибке установки модуля мастер останавливается до смены Home и очистки; ранее установленный APK лаунчера остаётся. **«Только обновить»** всегда исключает модуль, независимо от галочки. В обычном плане обновления можно отдельно выбрать установку или обновление AirPlay без удаления данных.

Модуль распространяется отдельно от MIT-лаунчера по GPLv3. В расширенном мастере кнопка **«Лицензия и исходники AirPlay»** копирует соответствующий архив исходников и лицензию в `PeachOS-TV-data/AirPlay` и открывает эту папку. Сборка с модулем должна включать полный соответствующий исходный код, инструкции и зависимости для сборки, а также исходные лицензии всех компонентов. Без APK модуля этот пункт недоступен; обычный portable EXE и самостоятельный APK лаунчера остаются доступны.

1. Скачайте **один файл `PeachOS-TV-Setup-Portable.exe`** в папку с правом записи. ADB, его DLL, APK, Python/Tk и лицензии уже внутри; внешние библиотеки и ручная распаковка не нужны. При запуске служебные библиотеки автоматически извлекаются во временную папку.
2. Вкладка «Устройство»: включите отладку на ТВ, подключите ПК и ТВ к одной сети. Запустите EXE, укажите IP:порт (обычно 5555) или USB-серийный номер. После «Подключиться» мастер откроет окно ожидания: подтвердите разрешение на экране ТВ. Ожидание длится до двух минут, его можно отменить. При беспроводном сопряжении с динамическим портом сначала выполните штатное `adb pair` из Android Platform Tools; ввод pairing-кода мастер пока не поддерживает.
3. В разделе «Приложения» выберите установку PeachOS. Кнопка «Добавить APK…» позволяет выбрать сразу несколько обычных APK с ПК, добавить ещё или убрать выбранные. Они попадут в план и установятся по очереди. Во вкладке «Очистка» выберите очистку и при необходимости назначение Home. Очистка изначально выключена: можно установить только лаунчер. Штатный Home по умолчанию не отключается.
4. Отметьте функции, которые нужно сохранить. Найдите ненужные пакеты по категориям или поиском. Галочка в таблице означает **отключить**, а не сохранить. Уже отключённые пакеты не меняются.
5. Нажмите **«Посмотреть план»**, прочтите последствия для каждого пакета и затем **«Применить этот план»**.
6. Проверьте приложения, микрофон, пульт, удержание громкости, HDMI и сеть. Если дальнейшая отладка не нужна, выключите её на ТВ и отзовите разрешение компьютера.

Кнопки **«Сохранить выбор» / «Загрузить выбор»** переносят выбранные пакеты и сохраняемые функции между запусками. При загрузке список заново фильтруется по подключённому устройству и текущему режиму: в обычном режиме неизвестные, защищённые и несовместимые пакеты пропускаются; в экспертном доступны все установленные пакеты. Это не команда применить очистку; план всё равно нужно просмотреть и подтвердить.

## База CleanYourTV и границы универсальности

Встроены 116 описанных кандидатов и справочный индекс 1403 имён пакетов из 260 списков устройств CleanYourTV. Индекс воспроизводимо собирается скриптом `import_reference.py`; исходный снимок: [ab7a89e7](https://github.com/Gathin23/cleanyourtv/tree/ab7a89e7543f2ef12aac0fa66a4d58c7f4452781/examples). Активные строки списков и закомментированные необязательные пакеты учитываются раздельно. Для найденного на устройстве пакета показываются исходные профили. Новый справочник включён прямо в EXE и работает без интернета.

**Справочный индекс не является разрешением отключить всё из него.** Пакеты, которые встречаются только в чужих модельных списках, отмечены «CleanYourTV — требуется проверка» и остаются недоступными в обычном режиме. Их можно выбрать в экспертном режиме после предупреждения. Подтверждённые по назначению общие кандидаты доступны вручную: ACR/аналитика, рекомендации, магазинные демонстрации, ненужные приложения и необязательные функции. Новые кандидаты не выбираются автоматически.

Применён подход upstream: сверка пакетов конкретного устройства, разделение по назначению, сохранение нужных функций, `pm disable-user`, запись состояния до команды и проверка результата. Единого списка безопасного мусора для всех Android/Google TV не существует: даже setupwraith и служба пульта могут обслуживать Wi-Fi, Cast или микрофон. Объявлять их универсальным мусором нельзя.

## Что универсально, а что зависит от модели

База состоит из общих кандидатов и точных модельных профилей. Сейчас подтверждённые профили: Xiaomi **MiTV-AESP0 / Android 9** и TCL **G10_4K_GB / Android 12**. При несовпадении модели или версии Android их правила не предлагаются. На остальных устройствах доступны общие кандидаты и пользовательские приложения. Каталог расширяется в `catalog.py`, где у каждого пакета есть назначение, профиль и зависимость от функции.

Это **не список безусловно ненужных сервисов**. Метрики отделены от рекламы, фоновых дополнений, предустановленных приложений и необязательных функций. Например, `com.tcl.ttvs` может отвечать и за аналитику, и за обновления; он не выбирается автоматически и защищён, пока отмечено «Сохранить обновления». Пакеты резервных копий, календаря, NFC и заставок не объявлены универсальным мусором. Netflix и Prime — пользовательский выбор, а не автоматическая очистка.

В обычном режиме неизвестные системные пакеты показаны для просмотра и **не отключаются**. В обычном режиме критические системные службы, текущий Home, SetupWraith (в том числе возможный владелец Wi-Fi), HDMI, пульт, Bluetooth, Play Services и магазин защищены. Службы с неизвестным назначением сначала нужно исследовать и добавить в проверенный профиль; поиск слова `analytics` в имени не является разрешением отключить пакет.

## Экспертный режим

Во вкладке «Очистка» можно отдельно включить экспертный режим после предупреждения. Он разрешает выбрать **любой установленный пакет**, включая неизвестные, системные, текущий Home, ADB, сеть и активные службы доступности. Защита сохраняемых функций не действует; галочки «Сохранить» становятся недоступными. При выключении режима опасный выбор убирается. Файл выбора сам по себе экспертный режим не включает.

Это отключение **пакетов** через `pm disable-user`, а не управление каждым процессом или Linux-службой. Ограничения прошивки и прав ADB остаются. Root не используется. Автоматически критические пакеты не выбираются; массовый выбор категории и выполнение экспертного плана требуют отдельного подтверждения.

**Отключение критических пакетов может привести к окирпичиванию устройства, потере загрузки, сети, пульта или ADB.** Если ADB перестанет работать, резервная копия мастера не поможет подключиться; может понадобиться сброс или перепрошивка. Экспертные операции журналируются так же, как обычные, но восстановление не гарантируется.

## Установка нескольких APK

В плане видны полные пути APK, которые будут установлены. Все файлы проверяются до первой установки; SHA-256 и результаты каждой установки сохраняются в журнале. Мастер использует `adb install -r`, не очищает данные и останавливается на первой ошибке. Уже установленные APK останутся на устройстве. Копия состояний пакетов **не откатывает установленные APK или их версии**. Split-наборы `.apks` / `.xapk` не поддерживаются: выбирайте самостоятельные `.apk` подходящей архитектуры.

## Копии, журналы и откат

На Xiaomi MiTV-AESP0 / Android 9 штатный Google Home может сохранять приоритет даже после ответа `Success` на назначение нового Home. Для этого профиля есть отдельная **выключенная по умолчанию** опция «Обход Home Xiaomi». Только если обычное назначение не помогло, мастер запускает PeachOS, обратимо отключает `com.google.android.tvlauncher` и проверяет выбор нового Home. Исходное состояние записывается в копию до отключения; при неудачной проверке мастер пытается сразу вернуть штатный Home. При обрыве соединения используйте «Восстановить из копии». Этот обход не применяется к другим моделям и не удаляет данные штатного лаунчера.

Папка `PeachOS-TV-data` создаётся **рядом с EXE**: внутри `backups` находятся копии, рядом — журнал и кэш ADB. Переносите эту папку вместе с EXE, если нужны прежние копии. Кнопка **«Открыть папку копий»** открывает её. ADB запускается из этого кэша, поскольку его сервер может работать после закрытия окна мастера; сервер не удерживает временную папку EXE. Старый ZIP-preview сохранял копии в `%LOCALAPPDATA%\PeachOS TV Setup\backups` — их можно выбрать вручную при восстановлении. Копия содержит сведения об устройстве и пакетах: не публикуйте её без просмотра.

Перед первым отключением читаются исходные состояния всех выбранных пакетов. Перед каждой изменяющей командой запись уже сохранена в `restore.json`: даже если ADB оборвался после выполнения команды, пакет можно вернуть. Мастер проверяет результат каждого отключения. При ошибке остановитесь, подключитесь заново и выберите **«Восстановить из копии»**. Копия от другого устройства или пользователя отклоняется.

Откат возвращает исходное `default`/`enabled` и исходный Home, если мастер его менял. Он **не удаляет APK**, не очищает аккаунты и не восстанавливает полную прошивку. Никаких `pm uninstall`, root, прошивки или очистки данных мастер не выполняет. Очистка не запускается автоматически после установки EXE или подключения устройства.

## Источники и разработка

Списки сверены с [CleanYourTV](https://github.com/Gathin23/cleanyourtv): профили `examples/xiaomi-mitv-aesp0` и `examples/tcl-g10-google-tv`, плюс локально проверенный список MiTV-AESP0. Из 30 отключений в пользовательской установке 28 относились к очистке, Netflix и Prime были отдельным решением. Эти данные не считаются подтверждением для других моделей.

Для запуска исходников нужен Python 3.12+ с Tk: `python wizard.py`. Тесты без изменений ТВ: `python -m unittest discover -s tools/pc-setup -p test_setup.py -v` из корня репозитория. Для сборки установите PyInstaller и запустите `build.ps1 -Apk <APK> -AdbDirectory <официальные platform-tools>`. В EXE включается [официальный ADB Google](https://developer.android.com/tools/releases/platform-tools) с его NOTICE. Все проверки применения/отката в автоматических тестах используют имитацию ADB, а не живые устройства.

Для сборки с необязательным AirPlay передайте вместе **все три** параметра: `-AirPlayApk <receiver.apk> -AirPlaySource <полный-исходный-код.zip> -AirPlayLicense <GPL-LICENSE>`. APK и GPL-архив не коммитятся в репозиторий лаунчера. Скрипт проверяет наличие манифеста и нативных библиотек в APK, наличие ZIP исходников и включает их под постоянными именами `PeachOS-AirPlay.apk`, `PeachOS-AirPlay-source.zip`, `LICENSE-AirPlay.txt`. Без этих параметров AirPlay не включается в EXE, в том числе при повторной сборке в ту же папку.

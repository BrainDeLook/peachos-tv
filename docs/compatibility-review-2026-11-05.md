PeachOS TV: ревью совместимости и план унификации
================================================

Дата: 5 ноября 2026 года. База проверки: опубликованный v1.5.15, commit `faf3ece`, minSdk 26, targetSdk 34.

Это ревью и проект изменений. Runtime-код, настройки устройств и опубликованные артефакты в ходе этой проверки не менялись. Устройства не перезагружались. Проверены установщик/Home, обработка пульта, системные действия, панель поверх приложений, источники, сеть и TV-метаданные. Это не новый полный аудит медиадекодеров AirPlay.

Основной вывод: охват расширит общий слой возможностей и проверяемых способов интеграции. Название производителя, включённая галочка или ответ команды `Success` сами по себе не доказывают работу функции. Один сбой необязательной функции не должен выводить из строя Home или всю панель.

**Архитектура унификации.**

Не нужен новый постоянно работающий менеджер. Нужен небольшой слой интеграции с общими контрактами, который вызывают APK и мастер ПК. Его можно вводить по одному backend без изменения внешнего вида.

Разделить три сущности:

1. `DeviceFacts`: API, Android user, признак TV/box, наличие системных features, семейство сборки, версии задействованных системных пакетов. Это сведения, а не обещание работоспособности.
2. `DesiredIntegration`: что включил пользователь — совместимый Home, Settings hold, overlay, переназначения. Выбор не теряется при временной недоступности службы.
3. `ObservedCapabilities`: что проверено, каким способом, когда и по какой причине не работает. У каждой функции есть состояние, backend и уровень доказательства.

Компактные состояния: `READY`, `NEEDS_USER_ACTION`, `UNSUPPORTED`, `TEMPORARILY_UNAVAILABLE`, `UNVERIFIED`. Причина отдельная: `PERMISSION_REQUIRED`, `SERVICE_DISABLED`, `SERVICE_NOT_BOUND`, `FILTER_DISABLED_BY_USER`, `PROVIDER_MISSING`, `TABLE_UNSUPPORTED`, `ACTIVITY_DENIED`, `SECURE_CONTENT`, `TIMEOUT`, `CONFLICT`. Не заменять всё двумя boolean `available/denied`.

Для пульта хранить последовательные факты: desired → enabled → bound → config applied после unlock → runtime filter requested → physical verified. Чтение флага не доказывает физическую обработку кнопки.

Внешний JSON/ADB ответ проверяется один раз на своей границе и превращается в типизированное значение. Дальше UI и policy работают с ним. Изменяемое состояние Android проверяется при соответствующем действии/событии, а не внутри каждого кадра и цикла. Исключения локализуются на реальных границах Binder/provider/startActivity, а не общим catch вокруг всего Home.

На API 29+ в APK стоит сначала проверять `RoleManager.isRoleAvailable(ROLE_HOME)` и предлагать `createRequestRoleIntent`, затем ACTION_HOME_SETTINGS при необходимости. Наличие role не гарантировано, а успешное назначение всё равно требует поведенческой проверки на OEM. Сейчас APK открывает только ACTION_HOME_SETTINGS. [Контракт RoleManager](https://developer.android.com/reference/android/app/role/RoleManager).

Способы интеграции должны иметь одинаковую семантику на ПК и в APK, но не одинаковые полномочия: APK не получает shell-привилегии автоматически. Обычный APK остаётся самостоятельным; ПК помогает только явно выбранным операциям. Проверка системы и ремонт отделены от безопасного update-only.

**Что доработать в установщике.**

- До любых изменений проверить пакет APK, minSdk, ABI, versionCode и совместимость сертификата с установленным приложением. Сейчас `inspect_apk` проверяет ZIP/manifest/ABI/hash, но не все эти свойства. Не предлагать удалить рабочий лаунчер как автоматическое решение signature mismatch. Текущую подпись нельзя просто заменить и сохранить обновление поверх.
- Подключение: USB, legacy TCP ADB и отдельный мастер pairing для прошивок, которые показывают «Беспроводная отладка». Pairing port и connection port — разные поля, `unauthorized`, `offline`, отказ сети и ожидание подтверждения — разные состояния. На TV стандартный wireless debugging документирован для Android 13+, а не для всех устройств API 30+. [Официальный ADB](https://developer.android.com/tools/adb#wireless).
- Пакетный план содержит before/target/result и durable journal перед мутацией; каждое действие имеет отдельные apply/verify/restore. После обрыва ADB сначала определить результат уже отправленной команды; не повторять всю установку вслепую.
- В backup добавить поколение операции/установки, версии backend и результат проверки. Старый backup не должен отключать позднее настроенные функции или возвращать устаревший Home.
- Сохранить exact-profile ограничения очистки. В справочнике upstream 442 списка устройств, но это не 442 аппаратно проверенных профиля PeachOS и не универсальный список безопасного отключения. Зависимости HDMI/tuner/сеть/пульт/настройки проверять отдельно от совпадения названия пакета.
- Не менять режим update-only скрытым включением служб. После чистой установки диагностика может предложить восстановить необходимые разрешения/интеграции отдельным понятным действием.

**Профили прошивок — данные с доказательством, а не исполняемые рецепты.**

Первый выбор определяется доступными API и успешным probe. Профиль нужен для исключений: известный ложный результат TIF, скрытый vendor connector, особая политика Home. Привязывать исключение к API/семейству fingerprint/версиям относящихся к функции системных пакетов, а не ко всей марке TCL/Xiaomi/Sony.

У каждого исключения: идентификатор, проблема, условия применения, допустимый backend, подтверждение и обязательные тесты. После OTA профиль перестаёт считаться подтверждённым до лёгкой повторной проверки; рабочая интеграция и службы автоматически не отключаются. `unknown` не означает «можно применить соседний профиль».

Первый вариант поставляется вместе с релизом и работает офлайн. Если позже понадобится независимое обновление каталога — только ограниченная схема данных, проверка подписи и совместимости версии, последняя рабочая копия. Никаких загружаемых shell-команд или автоматического включения новых cleanup-действий.

**Покрытие без обязательных пользовательских issues.**

Встроить экран «Проверка совместимости» в APK и тот же результат в ПК-мастер. Лёгкие probes запускаются при первом доступе к функции и после изменения соответствующих условий. На первом старте — только минимальное состояние без provider scans/dumpsys на критическом пути Home. Полный прогон запускается явно.

Экран показывает отдельные результаты Home, пульта, панели, входов, метаданных, сети и AirPlay. Например: «Пульт подключён к службе; фильтрация отключена настройкой», «Channels работает; Watch Next не поддерживается», «Home: программная проверка пройдена; пульт ещё не проверен».

Рядом — короткий мастер физических проверок: Home из приложения, короткий/долгий Settings, удержание громкости, Input, сон/пробуждение. Сохранять результат для текущей сборки прошивки, способа интеграции и транспорта пульта. Успех одного теста не подтверждает остальные.

Локальный отчёт JSON содержит версии, семейство прошивки, выбранные backend, статусы и коды причин, длительности этапов, результаты тестов и ограниченный технический журнал. По умолчанию исключить Android ID/serial/IP/MAC/SSID/BSSID, медиассылки/токены/заголовки, историю просмотра и содержимое экрана. Данные пульта для локальной привязки не копировать в публичный отчёт как уникальный descriptor.

Пользователь может экспортировать и передать отчёт, не составляя issue. Из согласованных отчётов строить таблицу совместимости и fixtures реальных ответов ADB/provider. Отдельно учитывать самоотчёт, автоматический probe и аппаратную проверку: один присланный отчёт не делает всю марку «поддержанной». Автоматическая фоновая отправка для первого этапа не нужна.

**Матрица тестирования и критерии готовности.**

| Уровень | Что проверять | Что он не доказывает |
| --- | --- | --- |
| Контрактные тесты Java/Python | Типизированные результаты, планы, ответы разных ADB/прошивок, конфликт rollback, недоставленный UP, две службы, границы таймаутов | Поведение реальной системной службы/OEM |
| Android instrumented на TV AVD | Чистая установка/обновление/удаление, grant/revoke, service bind/unbind/rebind, lifecycle окон, стандартный Home, рендер focus/clip | Физический HDMI/CEC, IR/Bluetooth пульт, vendor boot policy |
| Fault injection | Нет provider/таблицы, SecurityException, DeadObject/provider restart, signature-gated Settings, screenshot timeout/secure content, AppOps denial, частичная регистрация и обрыв ADB | Частоту появления на конкретной модели |
| Аппаратная матрица | TV и box; разные SoC/прошивки, родной пульт, CEC soundbar, HDMI/антенна, Ethernet/Wi-Fi, cold boot/sleep/OTA/reinstall | Все устройства того же бренда |
| Добровольные отчёты + preview | Неизвестные комбинации возможностей и прошивок, приоритет следующей аппаратной проверки | Достоверную производительность без воспроизводимого замера |

TV AVD официально поддерживаются [Android TV tools](https://developer.android.com/training/tv/get-started/create). Начать с представленных доступными образами границ API: 26/28, 30/31, 33/34 и более новых; отсутствие TV-образа для конкретного API нельзя скрывать обычным phone emulator в отчёте. Возможность исполнения сценария и аппаратная совместимость — разные показатели.

Для двух P1 и C03–C09 нужны регрессионные тесты до рефакторинга. Существующие SettingsKeyBindingTest отменяют обучение до DOWN и намеренно закрепляют игнорирование scan для обычного code; они не покрывают vendor collision и потерю UP. Тесты двух одновременно подключённых служб отсутствуют.

В тестах установщика `test_home_setup.py:366` проверяет конфликт bridge, но не продолжение независимого возврата пакетов; `:401` — один transient Peach, но не Stock после 0,4 с; `:339` — сохранение чужой службы, но не новое основание использования собственной. `test_setup.py:652` проверяет enable/default, но не более поздний выбор Home пользователем.

Для инструментальных тестов службы получать UiAutomation с `FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES`. Без этого сам тестовый инструмент по умолчанию подавляет службы Accessibility и создаёт ложный отказ Home/Settings. [Официальный контракт UiAutomation](https://developer.android.com/reference/android/app/UiAutomation#FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES).

Матрица lifecycle: свежий APK → отказ разрешения → выдача → отзыв; обновление поверх; clear data; uninstall/reinstall; force-stop → ручной запуск; смерть процесса; rebind; direct boot → unlock; sleep → wake; смена Android user; OTA. В каждой точке Home остаётся доступным, настройки не теряют выбор, необязательный отказ не становится общим crash.

Вводить изменения малыми preview: исправления отказов → общий пульт → общие системные действия/источники → диагностика/автотесты. На каждом шаге сравнивать Home и overlay на одном устройстве и не включать непроверенный backend всему семейству прошивок.

FPS и задержки сравнивать на реальном устройстве с той же release-конфигурацией, компиляцией, частотой экрана и сценарием. Фиксировать холодный/тёплый запуск отдельно, p50/p95 от порога удержания до первого кадра панели, jank/frame timing и PSS/CPU при закрытой панели. Эмулятор полезен для функциональных тестов, но не является доказательством 60 FPS на box; это прямо оговорено [Macrobenchmark](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-instrumentation-args).

**Ограничения, которые нельзя устранить одним универсальным перехватом.**

- Глобальная фильтрация Accessibility на отдельных прошивках меняет штатный путь громкости/CEC. Нужен выбор между проверенными режимами, без автоматического включения эмуляции громкости. Уже согласованный пользователем режим не менять из-за нового профиля.
- [AOSP указывает различия реализаций HDMI-CEC](https://source.android.com/docs/devices/tv/hdmi-cec). Программная команда с ПК не заменяет аппаратный тест пульта и саундбара.
- Для screenshot требуется подходящая API/capability; защищённый контент может отказать в снимке. [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService) документирует ошибки secure window/access/interval. Сохранять читаемый материал и объём без попыток обхода защиты. Ошибка снимка не должна задерживать/отменять саму панель.
- Сканирование Wi-Fi требует соответствующих разрешений и включённого Location, а Android ограничивает частоту. Не подменять Fine Location разрешением Nearby и не пытаться постоянно обходить throttling. [Wi-Fi scanning](https://developer.android.com/develop/connectivity/wifi/wifi-scan).
- На Android 13+ sideloaded Accessibility может попасть под restricted settings; нужен отдельный статус/объяснение и допустимый системный путь, если эта политика действительно присутствует на устройстве. Не предполагать её наличие на каждой TV-прошивке. [Android Help](https://support.google.com/android/answer/12623953?hl=en).
- Samsung Tizen/LG webOS и другие не-Android платформы не охватываются этим APK. В пределах Android 8+ тоже не обещать глобальный перехват системных кнопок там, где OEM не предоставляет рабочий путь.

**Порядок внедрения.**

1. Исправить C01/C02 и восстановление C03/C05/C06. Добавить негативные тесты, сохранив текущий визуал.
2. Исправить критерий Home C04 и lifecycle пульта C07–C09/C16. Общая служба учитывает основания использования; не ломать установленную схему обновления.
3. Общие Input/SystemAction/Sleep/Network adapters и изоляция ошибок C10–C15. Поведение функции одинаково на Home и поверх приложения.
4. Диагностика в APK/мастере, APK preflight и pairing. Небольшая аппаратная и TV AVD матрица как обязательная проверка релиза.
5. Версионируемые профили с доказательствами и добровольные отчёты; расширять подтверждённый охват по конкретным возможностям, не только по числу марок.

Уже удачные решения сохраняются: отдельное хранилище installer Home override, ограниченные очереди, временное окно overlay, уменьшенный screenshot и кэш размытия, остановка Wi-Fi при скрытии вкладки, Home-only без лишней фильтрации, обратимый disable-user и update-only без скрытых системных изменений. Непрерывный watchdog, фоновые сканы, периодические dumpsys и постоянный сбор клавиш для этой архитектуры не нужны.
